v9.9.331 · Antigravity 内部 Gemini REST 私有请求透传修复：最新红灯回归确认 `/v1internal:streamGenerateContent` 的私有 payload 不应被改造成公开 Gemini `contents` 或 `systemInstruction` 结构；上一版仍会在缺少公开字段时主动注入 `contents[].parts[].text`，存在继续触发内部契约 400 的风险。本版对 Antigravity 内部 `/vNinternal:*` Gemini REST 生成请求先行短路透传，只保留公开 `/vN:*GenerateContent` 的 `systemInstruction` 注入逻辑，并用 `gemini_internal_passthrough` 回归标记防止再次误改私有 payload。

v9.9.330 · Antigravity 内部 Gemini REST 承载修复：实机最新错误从 `Unknown name "systemInstruction"` 变为 `Unknown name "system_instruction"`，证明 Antigravity `daily-cloudcode-pa` 的 `/v1internal:streamGenerateContent` 私有契约同时拒绝两个公开 Gemini 顶层系统提示词字段。本版对内部 `/vNinternal:*GenerateContent` 改为“读取兼容、出站不造字段”：兼容读取 `systemInstruction` / `system_instruction`，出站删除二者，并把反转后的系统提示词前置到已有 `contents[].parts[].text` 承载；缺失系统提示词时同样注入到 contents。回归检查同步禁止内部 REST 再输出被拒顶层字段。

v9.9.329 · Antigravity Cloud Code REST 字段名修复：实机ZK模型返回 HTTP 400 `Unknown name "systemInstruction": Cannot find field`，而官方模式正常，证明请求已进入本地代理但上行 JSON 注入字段不符合 Antigravity `daily-cloudcode-pa` 内部 REST 契约。本版将 Gemini REST/SSE `generateContent` / `streamGenerateContent` 的系统提示词字段统一归一为 `system_instruction.parts[].text`，兼容读取旧 `systemInstruction` 但出站删除 camelCase，避免上游拒绝；同步升级回归检查，禁止包内再次输出被拒字段。

v9.9.328 · Antigravity Gemini REST/SSE 主请求注入修复：实机已证明 `--cloud_code_endpoint` 会被改写到本地代理，但真实聊天进入的是 `POST /v1internal:streamGenerateContent?alt=sse`，旧逻辑只把 `/vNinternal:*` 当官方 REST 初始化请求转发，未把 `streamGenerateContent` 归入可注入聊天链路，导致 `/origin/tape` 为 0、`systemInstruction` 原样上行。本版新增 Gemini REST 生成接口分类 `GEMINI_REST_CHAT`，在上游转发前改写 JSON `systemInstruction.parts[].text`，缺少 `systemInstruction` 时注入当前自定义/默认提示词；同时让 `/origin/tape` 与 `/origin/preview` 可观测这条 REST/SSE 请求。下行 SSE 响应仍保持官方原样透传，不改变 Antigravity 的原生流式解析。

v9.9.327 · Antigravity server 崩溃修复：实机日志确认 v9.9.326 已成功把 `--cloud_code_endpoint` 改写到 `http://127.0.0.1:8937`，但 15 秒延迟文件锚定后 `_maybeRestartLS()` 仍主动重启 Antigravity server-owned language server，随后 IDE 弹出 `Antigravity server crashed unexpectedly` / `connection to server is erroring`。本版在 `TARGET_IDE=Antigravity` 下禁止自动 `forceRestartLS()`，保留 spawn hook 改写与代理锚定，让官方 server 自主管理 LS 生命周期。

v9.9.326 · Windows 系统代理读取命令修复：v9.9.325 已让 Antigravity 回到 LS/CDP + HTTP proxy 模式，但新日志仍显示扩展激活阶段输出 `REG QUERY` 无效语法。根因是 `_readSystemProxy()` 用单条 `reg query ... /v ProxyServer /v ProxyEnable` 同时读取两个值，Windows `reg query` 不支持这种写法。本版改为分别读取 `ProxyEnable` 与 `ProxyServer`，消除激活期噪声错误，避免系统代理注入逻辑污染 Antigravity 启动链路。

v9.9.325 · Antigravity LS 初始化卡死修复：实机截图已进入 `Generating`，但代理 `/origin/tape` 仍为 0、`/origin/upstream` 为 null，系统进程里没有 `language_server_windows_x64.exe`，renderer 日志每分钟报 `LanguageServerClient must be initialized first!`。根因不是提示词未注入，而是 Pro 把 `Antigravity.exe` 误识别成 Devin ACP runtime，日志进入 `ACP模式 + HTTP代理双启`，同时解锁自愈在未见任何 LS spawn 时仍执行 `forceRestartLS` 并伪装成功，实际杀不到进程也无法启动 LS。本版将 Antigravity 明确归为 LS/CDP + HTTP proxy 模式，不再启 ACP stdio 代理；自愈逻辑在未见 LS spawn 时只记录并等待官方 LS 初始化，不再空杀。目标是先恢复官方 `LanguageServerClient` 初始化，再由 spawn hook 改写 `--cloud_code_endpoint` 进入本地代理。
